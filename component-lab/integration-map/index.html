Dependency order

Integration sequence

Wire shared primitives before page-level consumers so one fix propagates everywhere.

  1. Freeze foundations + image rules.
  2. Upgrade SP-PROD first; collection, search and recommendations depend on it.
  3. Integrate SP-NAV + SP-FOOT global shell.
  4. Repair the collection-template gap, then integrate SP-COL.
  5. Integrate SP-SEARCH, including predictive search as a separate adapter.
  6. Integrate SP-CART full cart, then add the drawer surface and connect header cart state.
  7. Carry SP-COMP-001–010 into their existing Sabpuja sections without cloning visual systems.
  8. Integrate SP-ACC only on theme-owned customer pages; keep Shopify-owned account/checkout surfaces outside Liquid.
  9. Run desktop/tablet/mobile visual QA, link crawl, accessibility pass and performance check on the unpublished staging theme before any publish decision.

Before theme integration

Known deltas to resolve

1 · Collection template is currently unresolved in GitHub.

templates/collection.liquid routes normal collections to sabpuja-collection-grid, but sections/sabpuja-collection-grid.liquid is not present. Create/restore that canonical section from approved SP-COL before any Shopify staging sync.

2 · Current product card is a subset of SP-PROD.

The existing snippet renders type, title, price and “View product”; it does not yet implement the approved compare-at/sale, sold-out, explicit-new, wishlist and optional secondary-image contracts. Upgrade the one snippet rather than creating another card family.

3 · Predictive search is not yet a current theme surface.

sections/sabpuja-search.liquid handles the full results page. SP-SEARCH predictive states need an adapter around Shopify predictive search, with keyboard/focus/loading/no-match behavior.

4 · SP-CART includes a drawer that the current full-cart section does not provide.

Keep sections/sabpuja-cart.liquid for the cart page, then add one global drawer surface connected to the header. Both must use Shopify cart state, not separate client-side truth.

5 · Account Journey is intentionally split.

Theme-owned legacy customer templates can adopt SP-ACC directly. Shopify-owned modern customer-account and checkout states must use supported extension surfaces; they should not be recreated with Liquid or fake authentication/payment state.

Gate rule: integration work may target only the verified unpublished Shopify staging theme. The live theme is not an integration target. After all mappings are wired, run a full visual QA + customer-facing link crawl before any publish decision.
