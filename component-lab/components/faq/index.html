SP-COMP-008 · Answer system

FAQ

Six fluid-first FAQ patterns for product, collection, campaign and support pages. Answers should stay factual, page-specific and visible whenever FAQ structured data is enabled.

Preview all variants at:

008A · Standard accordion

Default FAQ treatment for product and landing pages

Default

Frequently asked questions

Helpful answers before you choose

Keep the most important questions easy to scan and the answers concise.

What information belongs in this FAQ?⌄

Use questions that genuinely help a customer understand the product, preparation, ordering or support path shown on the current page.

Should the same answers be reused everywhere?⌄

No. Reuse the component structure, but keep answers specific to the product, collection or campaign where the section appears.

Can an answer include a helpful link?⌄

Yes. Link directly to the relevant product detail, policy or support destination when it helps the customer continue.

008B · Compact

Lower visual weight when FAQ is supporting rather than primary content

Lightweight

Quick answers

A smaller FAQ footprint

When should I use the compact variant?⌄

Use it when only a few questions remain after the page has already explained the main product or ritual context.

Does compact mean smaller touch targets?⌄

No. The visual treatment is lighter, but the summary rows remain comfortably tappable.

Can the first item start open?⌄

Yes. The production section includes an optional open-first setting.

008C · Two column

More questions without turning the page into one long vertical stack

Intrinsic grid

More detail

Questions that can sit side by side

The grid collapses naturally as available component width changes.

How does this adapt on narrow screens?⌄

Columns are created with an intrinsic auto-fit grid, so cards stack when there is no longer enough room.

Should answers be similar in length?⌄

Not necessarily, but concise answers make a multi-column FAQ easier to scan.

Can product links appear inside answers?⌄

Yes, when the link is directly useful to the question being answered.

What heading level should the section use?⌄

The production section supports H2 or H3 so the FAQ can fit the page's existing heading hierarchy.

008D · Grouped topics

Organize longer FAQs by meaningful subject rather than one undifferentiated list

Topic blocks

Browse by topic

Group related questions together

Product information

Questions about what the page or product communicates.

Where should current product details come from?⌄

Use the current Shopify product and approved content source rather than hard-coding changing commercial details into the component.

Can the FAQ explain ritual context?⌄

Yes, while leaving room for family, regional and priest guidance where practices vary.

Support

Questions about where the customer can go next.

What if a question is not answered here?⌄

Provide a clear route to the appropriate support or contact destination instead of stretching the FAQ beyond useful scope.

Can topic headings appear in other variants?⌄

The production section stores topic-heading blocks, but displays them only when the grouped-topics layout is selected.

FAQ paired with an explicit support path

When is this layout useful?⌄

It works well near the end of a product or campaign page where customers may still need help after reading the main content.

Does the support card stay visible?⌄

At sufficiently wide component widths it can remain sticky; on narrower widths it returns to normal document flow.

Should every FAQ include a support panel?⌄

No. Use this variant only when a support path materially helps the customer.

008F · Premium dark

High-contrast FAQ chapter for premium devotional landing pages

Sacred Brown

Before you continue

A deliberate closing FAQ chapter

Use dark treatment sparingly when the FAQ belongs inside an otherwise premium dark campaign sequence.

Does the interaction change in dark mode?⌄

No. Native details and summary semantics stay the same; only the visual treatment changes.

Are the colors still based on Sabpuja tokens?⌄

Yes. Sacred Brown, Temple Gold and Ivory are used to maintain the same component language.

Can this still output FAQ structured data?⌄

Yes, when the production setting is enabled and every visible question and answer is accurate for the page.

Production contract: one generic Shopify FAQ section controls variant, H2/H3 semantics, visible question blocks, optional topic headings, support panel, open-first behavior, section styling and optional FAQPage JSON-LD. Structured data must mirror the visible questions and answers; it should never contain hidden or unsupported claims.
